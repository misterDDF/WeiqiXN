## 未移除 Bug

### 联机请求数子流程停留在数子中且缺少结果双确认

- 状态：修复实现已落地，待联机运行验证后移除
- 记录日期：2026-05-22
- 涉及范围：局域网联机、数子协议、数子 UI 流程、终局结算
- 已观察行为：请求数子时发起方会一直显示“数子中”。
- 可见表现：发起数子后没有按预期进入对方请求确认、双方结果确认和终局结算的完整流程。
- 期望行为：发起请求数子后，先给对方弹请求窗口，同时发起方弹等待对方窗口；对方同意后再进行数子；数子结果返回后双方都弹数子结果确认窗口；双方都同意数子结果才结算对局；任一方不同意则弹出“有一方不接受结果”提示并继续对局。
- 当前处理：LAN 数子已拆成请求确认、host 计算、结果双确认和最终结算四段。发起方提交后显示等待对端确认弹窗；对端同意后双方进入数子中；host 广播候选数子结果后双方都弹结果确认窗口；双方都接受后 host 广播最终 `ScoreResultAccepted` 并结算，任一方拒绝则广播失败原因并弹出“有一方不接受结果”提示后继续对局。
- 移除条件：联机双方分别作为发起方测试数子，对方拒绝请求、同意请求后任一方拒绝结果、双方同意结果、KataGo 数子失败四条分支均能关闭等待界面，并保持双端对局状态一致。

### AI 对局不会在官子完成后自动进入数子

- 状态：修复实现已落地，待运行复现验证后移除
- 记录日期：2026-05-20
- 涉及范围：AI 对局、官子结束判断、数子流程
- 已观察行为：AI 模式下没有判断官子已经完成，也不会自动发起数子。
- 可见表现：AI 会持续落子填自己的活眼，直到没有合法点可落后报错。
- 期望行为：AI 对局进入应当数子的终局状态后，应停止继续生成普通落子，并进入数子流程，而不是继续填自己的活眼。
- 当前处理：`DuelAiSystem` 已接入 KataGo `pass` 决策；`moveInfos` 首选为 `pass` 或 `policy` fallback 中 pass 权重大于所有合法棋盘点时，AI 会走现有虚手事件。仍需用复现盘面验证打包/运行时不会继续填活眼。
- 移除条件：AI 对局能够稳定在终局阶段进入数子流程，并且不再持续填自己的活眼直到无子可落后，移除此条记录。
