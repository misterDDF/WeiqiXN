## 职责

UI 模块负责页面加载、页面栈、弹窗、Canvas 排序、UI 相机更新、页面缓存、UI 逻辑与自动生成 Binder 的连接。

## 当前进度

- UI 根节点和 EventSystem 会在 `UIManager.Init()` 创建并标记为 `DontDestroyOnLoad`。
- UI 按 `Loading`、`Header`、`General`、`TopMost` 等 context 管理；`TopMost` 使用安全的小枚举值，避免 Canvas sorting order 过大导致层级异常。
- 主页面使用栈结构，弹窗使用列表结构。
- 页面关闭后会进入短期缓存，超过 `UIConfig.PAGE_GAMEOBJECT_CACHE_TIME` 后销毁。
- 页面配置来自 `ui_page.json`，包含 context、是否弹窗、是否异步加载。
- `ConfirmPopup` 是通用二次确认弹窗，配置在 `TopMost` context，并由 prefab 根节点自带 Canvas 参与顶层排序。
- `DuelSetupPopup` 已支持选择 `9x9`、`13x13`、`19x19` 对局。
- `LoadingPage` 已用于启动阶段 AI 模型预热和场景异步加载进度展示，包含状态文案、详情文案、百分比和进度条。
- `DuelPage` 已支持显示调试状态、落子预览 VFX、鼠标左键落子、保存、退出和右下角常驻“形式”按钮；形式按钮会在“形式”和“关闭”之间切换，只发出 `OnRequestDuelOwnership` 或 `OnRequestClearDuelOwnership`，不直接读取或修改棋盘状态。形式按钮上方有默认隐藏的结果面板，用于显示 ownership 统计出的黑方目数和白方贴目后目数。
- UI Binder 代码可由编辑器工具生成。

## 设计观察

UI 逻辑和预制体引用通过 Binder 分离，适合后续继续扩展页面。UI 对棋盘落子的连接方式是事件驱动，`DuelPage` 不直接修改棋盘数据，这是健康边界。

## 风险和缺口

- `DuelPage` 直接读 `Input.GetKeyDown(KeyCode.Mouse0)`，代码中已有 `TODO input manager`。
- 非法落子没有用户提示，棋盘系统只是回退并返回。
- 当前对局页面上的当前玩家显示使用 guid，对玩家可读性不足。
- 保存有 `SavingPopup`，但加载存档的用户入口不明显。

## 后续建议

- 增加输入管理层，把鼠标/触摸/快捷键从页面逻辑里抽出。
- 为非法落子事件增加 UI 反馈通道，例如系统事件 `OnInvalidMove`。
- 对联机阶段预留房间页、匹配页、准备页、断线提示页，不要直接塞进 `DuelPage`。
