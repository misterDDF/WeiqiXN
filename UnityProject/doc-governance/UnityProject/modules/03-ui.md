## 职责

UI 模块负责页面加载、页面栈、弹窗、Canvas 排序、UI 相机更新、UI 逻辑与自动生成 Binder 的连接。

## 当前进度

- UI 根节点和 EventSystem 会在 `UIManager.Init()` 创建并标记为 `DontDestroyOnLoad`。
- UI 按 `Loading`、`Header`、`General`、`TopMost` 等 context 管理；`TopMost` 使用安全的小枚举值，避免 Canvas sorting order 过大导致层级异常。
- 主页面使用栈结构，弹窗使用列表结构。
- 页面关闭后会从所属 context 移除并销毁对应 GameObject；页面实例不做短期缓存，重新打开页面会重新加载 prefab 并执行完整加载生命周期。
- 页面配置来自 `ui_page.json`，包含 context、是否弹窗、是否异步加载和场景退出时是否自动关闭；`UIManager` 在主场景退出时按该配置清理所有 context 中需要随场景关闭的页面和弹窗，`LoadingPage` 保留为可跨场景加载页。
- 页面运行时加载后会统一强制根 `CanvasScaler.referenceResolution`：Unity Editor 默认使用 PC `1600x900`，可由不纳入版本库的本地 `UserSettings/UIRuntimeCanvasResolution.json` 覆写以便 Play 模式预览不同布局；PC 包使用 `1600x900`，Android 和 iOS 包使用竖屏 `720x1280`。Prefab 上保存的 CanvasScaler 尺寸只作为编辑器预览值，不作为实际运行时平台策略。
- Page prefab 的根节点是 Unity Canvas 根节点，根 `RectTransform`、`Canvas`、`CanvasScaler` 和 `GraphicRaycaster` 只维护编辑器和运行时 Canvas 结构，不用于页面铺满布局。已验证可正常预览的 Page prefab 根节点通常保持 Unity Canvas 编辑态零尺寸结构（如 `localScale=(0,0,0)`、`anchorMin=(0,0)`、`anchorMax=(0,0)`、`anchoredPosition=(0,0)`、`sizeDelta=(0,0)`、`pivot=(0,0)`）并使用 `Screen Space - Camera`；不要把根节点改成四向 Stretch 或 `Screen Space - Overlay` 来做页面布局，否则容易诱发 Unity Prefab 预览创建 `Canvas (environment)`。页面内容应放在根节点下的 `PanelRoot` 或既有等价内容根节点，由内容根使用四向 Stretch 铺满 Canvas。
- `StateRoot` 可在 prefab 上直接保存少量 UI 布局状态，当前支持 `RectTransform`、显隐和 `VerticalLayoutGroup` 的状态化应用；需要横竖屏状态切换的页面/弹窗使用 `PanelRoot` 下首个空节点 `sr_platform` 承载 `StateRoot`，并通过 Binder 字段 `sr_platform` 调用；横竖屏判断统一使用 `UIUtils.IsPortrait`，`MainMenuPage`、`DuelSetupPopup`、`UserInfoPopup` 和 `OgsFriendProfilePopup` 根据 `PanelRoot` 或等价布局根的宽高比在运行时切换 `Landscape` / `Portrait` 状态。后续新增页面/弹窗多状态固定表现时，同样优先使用 `StateRoot` 保存状态差异，页面代码只选择状态，不逐项设置表现组件属性。
- `ConfirmPopup` 是通用确认弹窗，配置在 `TopMost` context，并由 prefab 根节点自带 Canvas 参与顶层排序；它支持二次确认模式、提示模式、阻塞等待模式、可取消等待模式和输入框模式，提示模式只显示一个居中的确认按钮，不显示取消按钮，可取消等待模式只显示一个居中的取消按钮，输入框模式用于少量文本编辑场景。`ConfirmPopup` 默认随主场景退出关闭，并会清理尚未打开完成的静态 pending 请求，避免对局或复盘流程中的阻塞弹窗残留到后续场景。
- `DuelMoveConfirmPopup` is a `Header` context popup used only by portrait `DuelPage` move input. It contains confirm, cancel, and four directional adjustment buttons, does not install a full-screen blocking raycast layer, and leaves board-space click/touch-drag input available so the pending preview stone can be repositioned before confirmation. Confirming forwards through the existing duel move submission events; replay UI does not open this popup.
- `UIManager.Init()` creates a persistent high-depth `UICamera` under `uiRoot`. Page canvases bind to this dedicated UI camera instead of a scene `Main Camera`; `UIManager.sceneCamera` tracks the active scene camera for board-space pointer rays. The UI camera renders only the `UI` layer, uses `CameraClearFlags.Nothing` so it does not clear scene color, and loaded UI page/widget instances are recursively assigned to the `UI` layer at runtime; the scene camera excludes the `UI` layer at runtime. Page prefab canvas `PlaneDistance` values should remain at the Unity default `100`.
- LAN 对局断线等待重连复用 `ConfirmPopup` 提示模式，内容显示已等待秒数，唯一按钮为“退出主菜单”；按钮会离开当前 LAN 会话并返回主菜单。等待重连开始时 `DuelPage` 会关闭数子/悔棋等待弹窗，避免多个阻塞弹窗叠加。
- `UserInfoPopup` 展示本地资料卡、OGS 账号卡和功能入口区。本地资料卡展示本地姓名、小字号 ID、胜场、负场和“修改”按钮，修改姓名时打开 `ConfirmPopup` 输入框模式，确认保存后刷新资料页；OGS 登录不会覆盖本地用户名。弹窗 prefab 使用 `sr_platform` 上的 `StateRoot` 保存 `Landscape` 和 `Portrait` 两套布局，并使用 OGS 卡片内的 `sr_ogs_account` 保存 `LoggedOut` / `LoggedIn` / `Loading` / `Error` 四种账号状态，页面逻辑只切换状态。OGS 卡片未登录时显示简略未登录信息和登录按钮，点击登录会打开 OGS 浏览器授权；桌面/Editor 走 localhost callback，Android/iOS 玩家包发给 OGS 的回调地址走 `https://leo-zhang-git.github.io/weiqixn-oauth-redirect/ogs/callback/`，再由该静态页跳回 `weiqixn://ogs/callback` deep-link。登录后显示 OGS 用户名、ID、头像、地区、注册时间、标签、简介、综合等级/分数、排名和 19 路/13 路/9 路等级信息，并显示刷新和退出登录入口。最近对局列表不再内嵌在资料弹窗中，页面只读取复盘索引中 `isArchived` 的有效记录并显示数量摘要和独立列表入口；点击入口会打开独立 `RecentReplayListPopup`，该弹窗用 `sr_platform` 做横竖屏适配、用 `sr_recent_replay_state` 管理加载/空态/错误/内容状态，并复用 `ReplayArchiveItemWidget` 按按钮分页展示复盘索引条目；最近对局页不提供手动刷新按钮，错误状态保留重试入口。OGS 好友入口会打开独立 `OgsFriendListPopup`，该弹窗用 `sr_platform` 和 `sr_ogs_friend_state` 管理未登录、加载、空态、错误和内容状态，登录态下通过 `OgsConnectionService.RequestFriendListAsync` 读取 `GET /api/v1/me/friends/`；打开时若服务层已有启动/登录后预拉取或最近一次成功请求写入的第一页展示快照，会先立即展示该快照并静默刷新，静默刷新失败时保留当前列表，没有快照时才进入加载态；打开后每 5 秒自动刷新一次，不提供手动刷新列表按钮。列表项由 `OgsFriendItemWidget` 动态实例化，按实际可用高度分页，头像 URL 存在时异步下载展示，OGS 响应缺少等级、地区或在线状态字段时以空值降级，点击好友条目会打开独立 `OgsFriendProfilePopup` 展示好友资料详情。`OgsFriendProfilePopup` 用 `sr_platform` 保存 `Landscape` 和 `Portrait` 两套布局，竖屏保留紧凑资料卡样式，横屏使用更宽的 PC 弹窗布局；当前只展示好友响应中已解析或可空降级的头像、OGS ID、地区、综合等级/分数、排名、19 路/13 路/9 路等级、注册时间、简介和在线状态，头像 URL 存在时异步下载展示，并提供“邀请对局”和“删除好友”两个固定入口；删除好友会先打开二次确认弹窗，确认后调用 OGS 好友删除接口并关闭资料弹窗；邀请对局会复用 `DuelSetupPopup.OpenForOgsFriend` 打开 OGS 好友参数设置，按 `duel_handicap.ogsFriendEnabled` 展示精确让子选项，确认后向该好友发起 OGS challenge，发起方等待接受期间显示可取消阻塞弹窗，等待不会因固定时长超时自动报错，只通过取消按钮主动结束；对方拒绝时关闭等待并提示“对方已拒绝邀请。”，对方接受后进入对局前切换为不可取消阻塞弹窗。主菜单、普通对局、OGS 对局和复盘场景下 `OgsChallengeInviteCoordinator` 会在已有 OGS session 时每 2 秒读取 `GET /api/v1/me/challenges/?page_size=30`，只对 `challenged` 为当前 OGS 账号的入站 challenge 弹出接受/拒绝确认；接受邀请仍要求 write-capable session，对局场景接受邀请会先按本机玩家提交认输并返回主菜单，复盘场景接受邀请会先返回主菜单，再显示进入 OGS 对局的不可取消阻塞弹窗；拒绝邀请调用 `DELETE /api/v1/me/challenges/{id}/`。
- `OgsFriendListPopup` 顶部栏固定维护添加好友和好友申请入口；添加好友复用 `ConfirmPopup` 输入框模式输入数字 OGS ID，成功发送后只显示结果提示。好友申请按钮在普通好友列表模式下刷新未处理申请数量并在按钮文案中显示，点击后切换到申请列表并显示为“好友列表”，再次点击返回普通好友列表；申请条目仍复用 `OgsFriendItemWidget` 展示申请方资料，点击后通过 `ConfirmPopup` 提供同意/拒绝操作，处理成功后从当前列表移除并刷新数量提示。主菜单 `btn_user_info` 和 `UserInfoPopup` 的 OGS 好友入口会在已登录且存在未处理好友申请时显示 prefab 红点，红点显隐由 `OgsConnectionService` 的申请数量状态和统一数量变更事件控制。好友资料页删除好友成功后会通知当前打开的好友列表页立即静默刷新当前页，避免等待 5 秒自动刷新造成残留。
- `ReplayPage` 是当前本地复盘 HUD 控制层，配置在 `ui_page.json` 的 `Header` 页面层级并随 `ReplayScene` 生命周期打开和关闭。复盘记录由 `ReplaySystem` 通过 `save/replay/{gameId}/DuelRecord.json` 加载并在场景棋盘上重建，页面只显示状态、当前手数、当前手详情、图表和控制按钮，并把浏览命令和试下输入转发给系统；复盘场景相机会把棋盘放在画面偏左位置，为右侧分析面板保留空间，普通对局相机仍按棋盘居中取景；鼠标右键同样触发前一手。当前支持前5手、前一手、后一手、后5手浏览，以及从任意主线局面进入试下、连续试下落子、在试下分支内前后浏览和退出后恢复主线；普通复盘状态下在棋盘自主落子会自动进入试下并把该点击作为试下第一手，试下取消按钮只在试下模式中显示。AI 分析按钮在渲染完成后会切换为“关闭ai推荐”，再次点击会清理当前复盘棋盘上的 AI 推荐点和 ownership 覆盖层；AI 推荐开启时点击推荐点，会由 `ReplaySystem` 在试下分支中按缓存 `pv` 自动补完后续合法变化。试下输入复用 `DuelPageBoardInputController` 的棋盘命中与合法预览，不写回原始复盘归档，也不进入普通对局权威提交路径。胜率/目差图表在 `ReplayScene` loading 阶段生成有界种子采样，页面打开后后台补齐剩余手数；用户点击 AI 分析时，当前手图表补算和后台图表补齐会让路，AI 分析结束后再按适用状态恢复。图表区同时绘制胜率-手数与目差-手数折线，图表区域包含静态同色图例标识胜率和目差，拖动时显示目标手数预览，松手后跳转到对应主线手数；AI 推荐列表区域仍仅占位。
- 移动端玩家包的 `ReplayPage` 不主动发起复盘曲线高精度刷新和当前手高精度补算请求；AI 分析按钮返回的当前主线手结果仍会回写该手胜率/目差图表点，用 AI 选点分析结果兜底更新当前手曲线精度。
- `MainMenuPage` 包含局域网联机入口，点击后打开 `LanRoomPopup`；页面 prefab 使用 `sr_platform` 上的 `StateRoot` 保存 `Landscape` 和 `Portrait` 两套布局，横屏保留左侧菜单栏，竖屏切换为居中的大按钮布局。
- `LanRoomPopup` 是局域网联机入口弹窗，当前维护创建房间、搜索房间、房间列表容器和状态文本；房间行由 `LanRoomItemWidget.prefab` 动态实例化到纵向列表容器中。创建房间会先复用 `DuelSetupPopup` 选择棋盘、时间配置、让子配置和 host 座位，确认后再通过 `LanRoomService` 创建 host 房间、刷新 UDP 搜索到的房间列表，在点击房间行时发起 TCP 加入握手，用现有状态文本展示最小准备/开局状态，并在开局状态到达后进入带 LAN 标记的 `DuelScene`。
- `DuelSetupPopup` 已支持选择 `9x9`、`13x13`、`19x19` 对局、持有时间、读秒、让子和开局座位，并可作为 LAN 创建房间、OGS 自动匹配和 OGS 好友邀请前的参数设置弹窗复用；本地对局隐藏开局座位选择，电脑对局、LAN 创建房间和 OGS 好友邀请显示 `猜先` / `执黑` / `执白`，OGS 自动匹配隐藏开局座位选择并强制分先。让子下拉框包含分先、让先和当前棋盘可用让子数，OGS 自动匹配只保留分先，OGS 好友邀请按 `duel_handicap.ogsFriendEnabled` 展示精确让子选项且 `猜先` 时强制分先。弹窗按本地对局、电脑对局、LAN 创建房间、OGS 自动匹配和 OGS 好友邀请五种模式分别从用户存档读取并在关闭时保存当前选择，读取时会校验配置 id，缺失或失效时回退到默认选项。弹窗横竖屏布局状态由 `PanelRoot` 下首个空节点 `sr_platform` 上的 `StateRoot` 维护，页面逻辑通过 Binder 字段 `sr_platform` 调用，不直接查找组件；竖屏状态下主面板全屏铺满，选项居中展示，设置项标签和选项控件使用上下结构，棋盘预览整体缩小以避免超出屏幕。
- 运行时 UI 展示文案由 `message.json` 提供，代码通过 `MessageText` 按 key 读取或格式化；固定 prefab 初始文本仍由 prefab 显式维护。
- `LoadingPage` 已用于启动阶段 AI 模型预热和场景异步加载进度展示，包含状态文案、详情文案、百分比和进度条；它支持临时进度区间映射，Android 首启用该能力把主菜单场景加载限制在最后 98%-100%，关闭页面后恢复默认 0%-100% 区间。
- `DuelPage` 已支持显示黑白双方显示名、人类/AI 身份、当前行棋状态和主时间；电脑对局的人类座位显示本地用户名，LAN 对局座位显示同步到的玩家姓名。开启读秒时显示剩余读秒次数和读秒时间，未开启读秒时隐藏读秒信息。页面提供合法落子预览 VFX、鼠标左键落子、保存、退出和右下角常驻“形式”按钮；形式按钮会在“形式”和“关闭”之间切换，只发出 `OnRequestDuelOwnership` 或 `OnRequestClearDuelOwnership`，不直接读取或修改棋盘状态。形式请求发出后会先显示计算中状态，收到 ownership 结果后显示黑方目数和白方按当前让子配置贴目后的目数；分先、让先和让子使用不同括号文案。
- `DuelPage` 设置面板包含请求数子、悔棋、认输、保存、退出和关闭入口；悔棋只发出 `OnRequestDuelTakeBack` 并显示系统返回的动作提示，不直接重建棋盘，成功悔棋后会同步清理当前 AI 推荐点和 ownership 覆盖层。
- `DuelPage` 的代码职责已拆分：页面类保留生命周期、事件注册和按钮命令转发；`DuelPageBoardInputController` 负责棋盘鼠标命中、合法预览棋子生命周期和点击落子坐标输出；`DuelPageHudView` 负责玩家信息、形势结果、数子确认文案、终局面板、动作提示和设置按钮状态；`DuelPageInteractionState` 负责输入可用性、悔棋、认输、AI 身份和读秒显示判断。
- UI Binder 代码可由编辑器工具生成。

## 设计观察

UI 逻辑和预制体引用通过 Binder 分离，适合后续继续扩展页面。UI 对棋盘落子的连接方式是事件驱动，`DuelPage` 不直接修改棋盘数据，这是健康边界。对局页内部的输入、显示和可用性判断已有独立代码落点，后续新增按钮或 HUD 状态时应优先放入对应拆分类，而不是继续堆叠到页面生命周期类。

## 维护约束

- `MainMenuPage.prefab` 的主菜单按钮栈和其布局容器默认视为受保护区域，尤其是 `panel_buttons` 一类承载既有按钮排列的节点；除非任务明确要求调整主菜单布局，否则不得修改这些节点的 `RectTransform`、`LayoutGroup`、`ContentSizeFitter`、锚点、尺寸、间距或父子关系。
- 调整 `MainMenuPage` 横竖屏布局时应优先修改 `StateRoot` 中对应状态并通过 Inspector 的 `Apply` / `Capture Current` 工作流保存，不应在页面业务逻辑中硬编码具体布局数值。
- 当 UI 有可枚举的状态切换时，例如横竖屏、折叠/展开、等待/结果、模式面板、固定按钮组显隐或布局参数变化，应在 prefab 中用 `StateRoot` 维护状态并通过 Binder 暴露的状态枚举/方法切换；业务代码只负责根据条件设置状态。不要在页面逻辑里散落 `RectTransform`、`VerticalLayoutGroup`、`GameObject.SetActive` 等固定表现控制。运行时文本、数值、进度条、动态列表项和临时实例化对象仍由页面或对应 View 代码按数据刷新。
- 所有 `Assets/UI/Prefab/Page/*.prefab` 的 Canvas 根节点 `RectTransform` 不得作为铺满布局目标；不得因新增按钮、文本、Binder 节点或横竖屏适配修改 Canvas 根节点的缩放、锚点、尺寸或父子关系，尤其不得把已验证的零尺寸根节点改成四向 Stretch。页面铺满布局统一由根下 `PanelRoot` 或既有等价内容根承担，内容根应使用 `anchorMin=(0,0)`、`anchorMax=(1,1)`、`anchoredPosition=(0,0)`、`sizeDelta=(0,0)` 和 `scale=(1,1,1)`。
- 修改 `Assets/UI/Prefab/Page/*.prefab` 时，Canvas 根节点、Canvas、CanvasScaler、GraphicRaycaster、`PanelRoot`、主面板根节点、布局容器和棋盘承载节点默认不属于普通控件变更范围；新增按钮、文本或绑定时只应修改目标面板子树和 Binder 引用。通过右键 Page prefab 的预览平台菜单切换 CanvasScaler 预览尺寸是例外；该菜单还会写入被忽略的本地 Editor 运行时预览配置，让 Editor Play 模式使用同一分辨率基准，但不改变玩家包运行时分辨率策略。
- `DuelPage.prefab` 的 Canvas 根节点必须保持 Unity Canvas prefab 结构，页面铺满布局应由根下 `PanelRoot` 或等价承载节点负责；根 `RectTransform` 不应因新增设置项、按钮或 Binder 节点而改变缩放、锚点、尺寸或父子关系。
- prefab 修改后必须用 diff 检查是否出现非目标节点的 `RectTransform`、`Canvas`、`CanvasScaler`、`LayoutGroup` 或 `ContentSizeFitter` 变化；发现这类变化时先恢复布局脏改，再继续 Unity 编译验证。
- 使用编辑器脚本修改 Page prefab 时，脚本必须在加载 prefab 后捕获 Canvas 根节点、`PanelRoot`、主面板根节点和任务相关受保护布局节点的关键序列化值，并在保存前显式恢复。保护清单至少覆盖 Page prefab 根 `RectTransform.localScale`、`pivot`、锚点、`anchoredPosition`、`sizeDelta`、根 `Canvas.renderMode`，以及目标父节点以外受保护节点的 `RectTransform` 和布局组件字段；这是为了防止 Unity 保存 prefab 时自动归一化根节点或写入预览态布局。
- 静态图例、固定说明标签和固定按钮文案应放在 prefab 里维护，运行时代码只刷新动态摘要、进度、数值和状态。新增静态控件的编辑器脚本只能改目标父节点下的目标子树；运行后 diff 应只出现新增节点、目标父节点 `m_Children` 和必要 Binder 引用，不应出现 Canvas 根节点、`PanelRoot`、主面板根节点、布局容器或棋盘承载节点变化。

## 风险和缺口

- `DuelPage` 仍直接读 `Input.GetKeyDown(KeyCode.Mouse0)` 作为点击入口；棋盘命中和预览逻辑已拆到 `DuelPageBoardInputController`，但还没有通用输入管理层。
- 非法位置不显示预览棋子，页面不额外弹出无法落子提示。
- `ReplayPage` 当前已接入独立场景棋盘表现、基础手顺浏览、拖动预览跳转、胜率/目差折线图和试下分支，AI 推荐按钮已能在渲染后切换为关闭入口并清理现有 overlay，点击推荐点可展开缓存 `pv` 后续变化；仍未接入 AI 推荐列表联动。

## 后续建议

- 增加输入管理层，把鼠标/触摸/快捷键从页面逻辑里抽出。
- 保持合法预览作为非法位置反馈；如后续联机需要展示权威端拒绝原因，再基于 `OnDuelMoveRejected` 或等价事件接入。
- 对联机阶段预留房间页、匹配页、准备页、断线提示页，不要直接塞进 `DuelPage`。
