## 职责

UI 模块负责页面加载、页面栈、弹窗、Canvas 排序、UI 相机更新、UI 逻辑与自动生成 Binder 的连接。页面行为以 [SPECIFICATION.md](../SPECIFICATION.md) 为准，本文只记结构和维护约定。

## 当前进度

框架：

- `UIManager.Init()` 创建常驻的 UI 根节点、EventSystem 和 `UICamera`。UI 相机只渲染 `UI` 层，`CameraClearFlags.Nothing`。页面和 widget 实例运行时递归设为 `UI` 层，场景相机排除 `UI` 层；`UIManager.sceneCamera` 跟踪场景相机，用于棋盘射线。Page prefab 的 Canvas `PlaneDistance` 保持默认 100。
- context 有 `Loading`、`Header`、`General`、`TopMost` 等；`TopMost` 用较小的枚举值，避免 sorting order 过大。主页面用栈，弹窗用列表。页面关闭即销毁、不缓存，重开会重新加载 prefab。
- `ui_page.json` 配置 context、是否弹窗、是否异步加载、场景退出时是否关闭。主场景退出时按配置清理，`LoadingPage` 可跨场景保留。
- 运行时按画面方向设置根 `CanvasScaler.referenceResolution`：竖屏统一使用 720×1280；横屏 PC、Android/iOS 使用 1600×900，Editor 横屏默认 1600×900，可被不入库的 `UserSettings/UIRuntimeCanvasResolution.json` 覆写（由 prefab 预览平台菜单写入，见 10 号文档）。prefab 上保存的尺寸只是编辑器预览值；`DuelPage` 横竖屏切换时也会同步刷新画布基准。
- Binder 由编辑器工具生成。运行时文案来自 `message.json`，代码通过 `MessageText` 按 key 读取；prefab 上的固定文本由 prefab 维护。
- 弹窗过渡 `UIPageTransition`：
  - 调用关系：`UIPage.OnOpen` 调 `PlayOpen`；`UIManager.RecycleClosedPage` 调 `PlayClose`，过渡结束后销毁。
  - 运行时在内容根（`PanelRoot` / `panel_root`，没有包装层时为 `mask`、`panel_main` 等）上 GetOrAdd `CanvasGroup`，做 180ms 淡入淡出；窗口节点临时偏移 6px。名称含 `mask` 的节点只淡入不位移，新弹窗的遮罩必须这样命名。
  - 过渡中外部写入（如 StateRoot）视为新的静止位置。用 `Time.unscaledDeltaTime`；关闭时关掉 `blocksRaycasts` 并清除选中。
  - 主页面不过渡。`OnExitMainScene` 期间关闭的弹窗直接销毁，并调用 `CompleteAllClosing`。
- `StateRoot` 在 prefab 上保存 `RectTransform`、显隐和 `VerticalLayoutGroup` 的状态。横竖屏页面用 `PanelRoot` 下首个空节点 `sr_platform`，按 `UIUtils.IsPortrait`（布局根宽高比）切换 `Landscape` / `Portrait`。
  - 已有 `sr_platform` 的页面：`DuelPage`、`MainMenuPage`、`DuelSetupPopup`、`UserInfoPopup`、`RecentReplayListPopup`、`OgsFriendListPopup`、`OgsFriendProfilePopup`、`LanRoomPopup`、`ReplayPage`、`LoadingPage`、`ConfirmPopup`。
  - 其他状态节点：
    - `DuelSetupPopup.sr_mode`：`Local` / `Ai` / `Lan` / `Ogs` / `FreeLayout` 五种表现状态，OGS 好友对局复用 `Lan` 参数布局；六种业务模式仍独立保存偏好。`sr_board_preview` 选择 9/13/19 路静态示意，竖屏隐藏预览容器并保留动态方案摘要。
    - `ConfirmPopup.sr_dialog_layout`：`Landscape` / `Portrait` / `ScoreLandscape` / `ScorePortrait`；`sr_dialog_buttons`：`Both` / `ConfirmOnly` / `CancelOnly` / `Neither`，业务只选状态，不缓存旧按钮坐标。
    - `OgsFriendItemWidget.sr_row_mode`：`Normal` / `Invitation`，资料入口与同意/拒绝按钮互斥；处理申请期间暂时禁用行内提交按钮。
    - `UserInfoPopup.sr_ogs_account`：`LoggedOut` / `LoggedIn` / `Loading` / `Error`。
    - `RecentReplayListPopup.sr_recent_replay_state` 和 `OgsFriendListPopup.sr_ogs_friend_state`：加载、空态、错误、内容等。

V3 主题基础（令牌、字体、贴图、按钮反馈已就绪；V3.3 页面及三种列表行已实装，编辑态验证通过，Play 交互待验收）：

- 色板令牌在 `UIPalette`，色值以 [14-visual-polish-plan.md](14-visual-polish-plan.md) 为准。新代码中的颜色直接引用令牌，不写字面量。
- 字体：
  - Regular（`SourceHanSansSC-Regular SDF`）是 TMP 默认字体和正文字体。
  - `SourceHanSansCN-Medium SDF` 替换伪粗体；`SourceHanSerifCN-SemiBold SDF` 用于标题和结果。
  - 这两款是动态资产，fallback 到 Regular，和源 OTF 一起在 `font` AssetBundle 里。许可见 `Assets/UI/Font/THIRD_PARTY_FONTS.md`。
- 贴图在 `Assets/UI/Textures/Theme/`，都是白色 + alpha，由 `Image.color` 取令牌着色：
  - 九宫格（Sliced）：`ui_panel`、`ui_card_shadow`、`ui_button`、`ui_input`、`ui_toggle_box`、`ui_capsule`。另有滑条手柄 `ui_knob` 和 13 个图标 `icon_*`。
  - 面板、按钮、输入框和勾选框自带 1px 边，着 `Paper` 时等于 `Hairline`。
  - 柔影是面板后面的一张 Image：四边各大 16，下移 3，着 `Ink`，α 约 0.8。
  - 滑条和滚动条的轨道与填充用 `ui_capsule`。未勾选框和输入框用 `PaperSunken`。分隔线和遮罩用无 sprite 的 Image。
  - 胶囊进度条用右锚点 `anchorMax.x` 控制宽度，不用 Filled，否则圆头会被拉伸。
- 按钮：
  - ColorTint 只能压暗，所以底板 `Image.color` 置白，底色取 `UIPalette.PaperButtonColors` / `AccentButtonColors`：悬停 `PaperRaised`，按下 `PaperSunken`，选中等于常态，禁用时 α 为 `DisabledAlpha`。
  - `UIButtonFeedback` 负责子节点：按下时直接子节点下沉 1px；不可交互时文字和图标通过 `CanvasRenderer` 降到 45%，不改 `Graphic.color`。
  - 它只实现指针进出、按下和抬起，不会截走 `ScrollRect` 的拖动和滚轮。

页面结构：

- `DuelPage`：
  - 页面类只管生命周期、事件注册和按钮转发，其余拆成三个类：
    - `DuelPageBoardInputController`：棋盘命中；合法预览棋子，80ms 淡入淡出，通过 `MaterialPropertyBlock` 写 `_PreviewAlpha`；输出点击落子坐标。
    - `DuelPageHudView`：玩家信息、形势结果、数子文案、终局面板、动作提示和设置按钮状态。
    - `DuelPageInteractionState`：输入可用性、悔棋、认输、AI 身份和读秒显示的判断。
  - `sr_platform` 保存方案 E 横竖两态；玩家卡固定按棋色，横屏为棋盘左置 + 右栏，竖屏为顶部信息、白方卡、棋盘、黑方卡和底栏。`DuelActionLayoutGroup` 只负责同一组操作行在横屏纵排、竖屏横排，并在 LAN / OGS 隐藏分析行后重新等分。
  - 常驻按钮是虚手、形势和 AI 分析（LAN 和 OGS 隐藏 AI 分析）。设置面板横屏为右抽屉、竖屏为底抽屉；请求数子仍走既有等待/结果弹窗，自己发起的悔棋、认输和退出在抽屉内行内确认，空白遮罩或 Escape 关闭抽屉。
  - 页面只发事件，如 `OnRequestDuelOwnership`、`OnRequestDuelTakeBack`，不直接改棋盘。
- `DuelMoveConfirmPopup`：
  - `Header` context，只用于竖屏 `DuelPage` 的落子确认，以底部栏替换操作区，显示落点坐标、确认、取消和四向微调。
  - 不放全屏遮挡射线，点按或拖动棋盘仍能改落点；待确认点只显示半透明预览子。底栏显示期间隐藏常规动作栏，确认走现有的落子提交事件。复盘不用它。
- `ConfirmPopup`：
  - `TopMost` context，根 Canvas 参与顶层排序。
  - 模式：二次确认；提示（只有居中确认按钮）；阻塞等待；可取消等待（只有居中取消按钮）；输入框。
  - 普通确认横屏居中 600×430，竖屏全宽底部面板；数子结果为 480 高。两按钮等宽，单按钮居中；正文、输入框和回调复用原请求链路。
  - 随主场景退出关闭，并清理尚未打开完成的 pending 请求。LAN 断线等待重连也用提示模式。
- `ReplayPage`：
  - `Header` context，随 `ReplayScene` 开关。只负责显示和转发，浏览和试下输入交给 `ReplaySystem`；试下复用 `DuelPageBoardInputController` 的命中与预览。
  - 横屏棋盘左边距与上边距一致，右侧放手数、纸面图表和操作；竖屏棋盘居中，图表与手顺栏在下方。图表胜率用 `Analysis`，目差用 `Accent`，坐标轴用 `Hairline`。
  - 图表标题栏通过 prefab/Binder 的 `toggle_chart_black`、`toggle_chart_white` 切换黑白视角，默认黑方，没有自动选项。白方视角把黑方胜率转换为 `1-p`、黑方目差转换为 `-s`；目差显示所选方及正负号，正值领先、负值落后，接近零时显示均势。切换同步更新两条曲线、当前手摘要和拖动预览，仅影响显示，不改变分析数据、浏览游标或试下执子。
  - 手数游标用深墨色以适应浅纸底；折线采用连续连接、圆形端点与透明羽化边缘，保留真实采样折点。仅当前手存在对应样本时绘制圆形标记，缺失值不伪造数据。
  - 竖屏试下和自由布局的“交替落子 / 黑子 / 白子”组位于功能操作行下方、棋盘上方，随 `sr_platform` 布局状态切换；非试下隐藏，横屏保持右侧位置。
- `MainMenuPage`：横屏是左侧宣纸菜单栏叠在棋盘静物上，竖屏是下方宣纸抽屉叠在棋盘静物上；菜单行由编号、标题、说明和悬停朱色竖条组成，右上用户胶囊显示本地名与 OGS 状态。`btn_user_info` 上有 OGS 好友申请红点。棋盘静物由主菜单场景中的 `RectGrid`、对局棋盘材质和 3D 棋子预制体渲染，`MainMenuBoardBackdrop` 切换横竖屏取景，不参与棋盘规则。
- `UserInfoPopup`：本地资料卡、OGS 账号卡和功能入口区；最近对局和 OGS 好友都从这里打开独立弹窗。
- 列表弹窗：
  - `RecentReplayListPopup` 用 `ReplayArchiveItemWidget` 分页。
  - `OgsFriendListPopup` 用 `OgsFriendItemWidget`，按可用高度分页，也用来显示好友申请。
  - 两者的 `btn_refresh` 是错误态的重试按钮，不做手动刷新。
  - `OgsFriendProfilePopup` 是好友详情。`LanRoomPopup` 的房间行由 `LanRoomItemWidget` 动态生成。
- `OgsChallengeInviteCoordinator`：在主菜单、对局和复盘场景轮询 OGS 入站 challenge，并弹出接受/拒绝确认（见 11 号文档）。
- `DuelSetupPopup`：对局参数弹窗，复用于本地、电脑、LAN 建房、OGS 自动匹配、OGS 好友邀请和自由布局六种模式，每种模式单独保存偏好。横屏为棋盘示意与摘要侧栏、两列参数；竖屏为全宽底部纸面抽屉，棋盘按钮三等分、参数单列、读秒两列，轻量摘要与主操作相邻，抽屉高度随可见字段和摘要换行收缩。
  - prefab 内的 `DuelSetupPortraitLayout` 仅由 `sr_platform` 的 Portrait 状态激活，维护竖屏内容测量、等分、排版和短画布缩放；字体、颜色、对齐和间距保存在该组件，固定控件仍由 prefab 维护。Landscape 状态停用组件、恢复原外观和 GridLayoutGroup，并恢复参数行、下拉模板与关闭按钮的 RectTransform；业务页面不维护布局坐标。
- `LanRoomPopup`：横屏左侧建房卡与右侧附近房间列表，竖屏上下排列；列表使用既有 `LanRoomItemWidget` 并支持滚动。
- `LoadingPage`：深色背景、产品字标、状态说明与细线进度，继续用右锚点显示进度。
- `LoadingPage`：显示 AI 预热和场景加载进度。支持临时进度区间映射，Android 首启把主菜单加载映射到 98%–100%。

## 设计观察

UI 逻辑和预制体引用通过 Binder 分离。UI 对棋盘落子是事件驱动，`DuelPage` 不直接修改棋盘数据，这是健康边界。对局页的输入、显示和可用性判断已有独立类，新增按钮或 HUD 状态时优先放进对应拆分类，不堆到页面生命周期类里。

## 维护约束

- Page prefab 的结构保护以 [AGENTS.md](../AGENTS.md)「UI prefab 结构保护」为准：Canvas 根节点零尺寸结构、`PanelRoot` 负责铺满、受保护布局节点（含 `MainMenuPage` 的 `panel_buttons`）、编辑器脚本保存前恢复、改后检查 diff。
- 可枚举的固定表现状态（横竖屏、折叠/展开、等待/结果、模式面板、按钮组显隐）用 `StateRoot` 维护，通过 Binder 暴露，业务代码只选状态。不要在页面逻辑里散落 `RectTransform`、`LayoutGroup`、`SetActive` 这类固定表现控制；文本、数值、进度和动态列表由代码刷新。
- 调整横竖屏布局时，改 `StateRoot` 的对应状态，用 Inspector 的 `Apply` / `Capture Current` 保存，不在代码里硬编码布局数值。

## 风险和缺口

- `DuelPage` 仍直接读 `Input.GetKeyDown(KeyCode.Mouse0)`，还没有通用输入管理层。
- 非法位置不显示预览棋子，也不弹提示。
- `ReplayPage` 的 AI 推荐列表区域仍是占位。

## 后续建议

- 增加输入管理层，把鼠标、触摸和快捷键从页面逻辑中抽出。
- 联机需要展示权威端拒绝原因时，再基于 `OnDuelMoveRejected` 或等价事件接入。
- 联机相关页面独立成页，不塞进 `DuelPage`。
